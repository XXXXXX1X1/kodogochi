# Кодогочи 🐣

Виртуальный питомец команды разработчиков. Живёт в Telegram-чате команды и болеет от реальных проблем
репозитория на GitHub: упала сборка — заболел, PR третий день без ревью — грустит и зовёт команду,
починили — выздоровел. Пять суток красной сборки — умирает, а воскресить его можно только зелёной сборкой.

- Telegram-бот: `/start`, `/pet`, `/me логин`, `/disable`
- Страница питомца `/p/<ссылка>` с журналом за 14 дней и списком «Кто лечил»
- SVG-бейдж для README
- Реплики пишет Claude; если модель недоступна — русские шаблоны

## Правила питомца

| Событие в репозитории | Реакция |
|---|---|
| Сборка упала | Заболевает, пишет в чат. −20 здоровья за каждые полные сутки красной сборки |
| Сборку починили | Здоровье 100, благодарит того, кто починил |
| PR ждёт ревью дольше 48 часов | −10 настроения в сутки, зовёт автора и команду |
| PR проверили или приняли | +10 настроения, проверивший попадает в «Кто лечил» |
| Правка в основную ветку в пятницу после 18:00 | Паникует |
| 7 дней без правок | Засыпает |

Не больше 5 сообщений в сутки на чат, тишина с 23:00 до 09:00 по часовому поясу команды.
Числа меняются в `config/rules.toml`, реплики — в `config/templates.toml` и `config/prompts/system.txt`.

## Устройство

Один asyncio-процесс: FastAPI принимает webhook GitHub и отдаёт страницу, aiogram получает сообщения
long polling, APScheduler раз в час сверяет состояние с GitHub REST и начисляет суточные ступени.
Данные — SQLite (WAL) на постоянном томе.

```
GitHub ──webhook──▶ FastAPI ─▶ правила (rules.py) ─▶ SQLite ─▶ очередь ─▶ Claude/шаблон ─▶ Telegram
          REST ◀── сверка раз в час (APScheduler)          └─▶ страница и бейдж (web.py)
```

| Модуль | Что делает |
|---|---|
| `rules.py` | шесть правил, чистые функции без сети |
| `engine.py` | применяет правила к базе, пишет журнал и очередь |
| `webhook.py` | подпись HMAC, лимит 2 МиБ, дубли, нормализация событий |
| `github.py` | REST-сверка с кешем ETag, лимиты 403/429 |
| `notifier.py` | квота, тихие часы, склейка, ответы Telegram 429/403 |
| `voice.py` | реплика Claude с проверкой текста, шаблоны при сбое |
| `bot.py` | команды и пошаговое подключение в личном чате |
| `web.py`, `art.py` | страница, бейдж, рисунок питомца |
| `clock.py` | игровые часы: в демо сутки идут за минуту |

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dev.txt
.venv/bin/python -m pytest            # тесты правил, webhook, очереди, страницы
cp .env.example .env                  # заполнить BOT_TOKEN и PUBLIC_URL
set -a; . ./.env; set +a; .venv/bin/uvicorn kodogochi.main:app --port 8000
```

GitHub отправляет webhook только на публичный HTTPS-адрес, поэтому для настоящего репозитория нужен
сервер (или туннель). Без GitHub события можно прислать скриптом `scripts/simulate.py`.

## Запуск в Docker на сервере

```bash
docker compose -f deploy/compose.claw.yaml up -d --build
```

Переменные окружения — в `.env.example`. Перед контейнером нужен HTTPS-прокси (пример для Caddy —
`deploy/kodogochi.Caddyfile`). База и ежедневные копии (7 последних) лежат в томе `kodogochi_data`.

## Подключение репозитория

1. Добавьте бота в чат команды, администратор пишет `/start` и называет питомца.
2. Бот присылает кнопку в личный чат: там указываете `owner/repo`, workflow сборки и часовой пояс,
   соглашаетесь на публикацию страницы.
3. Бот выдаёт адрес и секрет. В репозитории: **Settings → Webhooks → Add webhook**, Content type
   `application/json`, события *Pushes, Workflow runs, Pull requests, Pull request reviews*.
4. GitHub присылает ping — бот пишет в чат «Репозиторий подключён». Участники пишут `/me логин`.

## Демо-режим

`TIME_SCALE=1440`: игровые сутки идут за 1 минуту. Вместе ускоряются пороги 48 часов, 5 и 7 суток,
тихие часы и пятничная граница. Сценарий для показа на тестовом репозитории
[kodogochi-demo](https://github.com/XXXXXX1X1/kodogochi-demo):

1. Изменить `status.txt` на `fail` → сборка красная, питомец заболел (сообщение через ~1 минуту после сборки).
2. Подождать 5 минут → здоровье падает по 20 в «сутки», на пятой минуте некролог.
3. Вернуть `ok` → питомец воскрес.
4. Открыть PR и не ревьюить 2 минуты → питомец грустит и зовёт автора.
